## 4. 行為組合（07-D06）

行為旗標的名稱照 RO 的行為（03 第 4.6 節）。第一版用到兩組，另外先定義常用的幾組：

| 組合 ID | 旗標 | RO 的 AI 類型 | 第一版 |
|---|---|---|---|
| `passive` | can_move、can_attack | 01 | ✔ |
| `passive_looter` | can_move、looter、can_attack | 02 | ✔ |
| `passive_assist` | can_move、assist、can_attack、change_target_melee | 03 | — |
| `aggressive` | can_move、aggressive、can_attack、change_target_chase | 05 | — |
| `aggressive_immobile` | aggressive、can_attack | 10 | — |
| `immobile` | （沒有旗標） | 06 | — |

| 旗標 | 意思 |
|---|---|
| can_move | 會移動（閒晃、追擊） |
| can_attack | 會普攻 |
| aggressive | 主動找視野內的玩家攻擊 |
| looter | 閒晃時會撿地上的物品，死亡時掉出來 |
| assist | 附近的同種怪物被攻擊時一起攻擊 |
| change_target_melee | 攻擊中被別人近戰打到，就換成打他 |
| change_target_chase | 追擊中被別人打到，就換成打他 |
| detector | 看得到隱匿中的玩家 |
| no_random_walk | 不閒晃 |

## 5. 伺服器 AI（07-D04～07-D09）

### 5.1 狀態

```text
             被攻擊／（主動型）視野內發現玩家
   閒晃 ──────────────────────────────────────► 追擊
    ▲  ▲                                          │  目標進入攻擊距離
    │  │  目標死亡、消失、隱匿、進安全區、            ▼
    │  └── 超過追擊距離、追不到 ─────────────── 攻擊
    │                                             │  目標離開攻擊距離 → 回到追擊
    │                                             │
   HP 歸零（任何狀態）────────────────────────► 死亡 → 移除 → 等待重生
```

| 狀態 | 做什麼 |
|---|---|
| 閒晃 | 每 4～5 秒走到附近隨機的一點（沒有 no_random_walk 時）；looter 先找視野內的物品去撿；aggressive 每次思考時找視野內最近的玩家 |
| 追擊 | 用導航網格走向目標；目標距離超過追擊距離（`chase_range_cells`）就放棄，回到閒晃 |
| 攻擊 | 照 06 第 6 節的普攻流程（揮擊條件、攻擊間隔、命中時間） |
| 死亡 | 給經驗、掉物品（06）；從地圖移除，其他人看到原因為「死亡」的消失（02）；開始計算重生時間 |

- 照 RO，怪物追丟目標後不會跑回生成點，就在原地閒晃（07-D04）。

### 5.2 思考（07-D05）

- 每隻怪物每 100 毫秒思考一次。伺服器 tick 是 33 毫秒，所以每個 tick 處理大約三分之一的怪物（用怪物 ID 分組錯開）。
- 移動、攻擊的排程照 01 第 6 節，不受思考間隔影響：思考只決定「要做什麼」。
- 地圖上沒有玩家時，AI 暫停；第一版直接卸載整張地圖（01 第 7.2 節）。

### 5.3 找目標與換目標

| 規則 | 內容 |
|---|---|
| 主動找目標 | 只有 aggressive；在視野（`skill_range_cells`）內、看得到、可以攻擊的玩家裡選最近的 |
| 不能當目標 | 抵達後 3 秒保護中的玩家（02-D16）；隱匿中的玩家（沒有 detector 時）；死亡的玩家；在安全區裡的玩家 |
| 反擊 | 被打的怪物如果沒有目標，就以攻擊者為目標（被動型也會反擊） |
| 換目標 | 依 change_target_melee、change_target_chase 旗標 |
| 協助 | assist 的怪物在附近的同種怪物被攻擊時，以同一個攻擊者為目標 |

### 5.4 撿東西（looter）

- 閒晃時在視野內找地上的物品，走過去撿。撿起來的物品存在怪物身上，死亡時跟掉落物一起掉出來。
- 撿取優先權（06 第 13 節）期間的物品，怪物不會撿。

## 6. 生成與重生（07-D08）

- 生成區是 logic 場景裡的 MonsterSpawnArea 標記（03 第 6.2 節），參數：怪物、數量、範圍、基本重生時間、隨機時間。
- 地圖載入時，每個生成區生成全部數量，位置在範圍內導航網格上隨機的點。
- 怪物死亡後，經過「基本重生時間＋0～隨機時間」在同一個生成區的隨機位置重生，至少 1 秒。
- 重生的怪物以原因「新出現」出現（02 第 9 節），客戶端可以播出現的特效。

**南方草原第一版的生成（參考 RO 的 prt_fild08，實際位置在 08）：**

| 怪物 | 範圍 | 數量 | 基本重生時間 | 隨機時間 |
|---|---|---|---|---|
| gelly | 整張地圖 | 25 | 5,000 ms | 0 |
| fluffy_caterpillar | 整張地圖 | 15 | 5,000 ms | 0 |
| young_treant | 樹林區 | 10 | 5,000 ms | 0 |
| gelly、fluffy_caterpillar | 河邊和農地附近的小群集 | 各 3 | 15,000 ms | 0 |

- RO 的 prt_fild08 是整張地圖 20 隻 Poring、20 隻 Lunatic、10 隻 Fabre，另有幾個 15 秒重生的小群集；南方草原比較大（約 500 × 500 m），數量相近、密度略低。實際體驗後再調。

## 7. 程序化動畫（07-D10、07-D11）

全部在客戶端，只用來表現，不影響伺服器的判定。參數放在怪物的外觀設定（`.visual.tres`）。

### 7.1 果凍怪（gelly）

| 狀態 | 做法 |
|---|---|
| 站立 | 頂點著色器的上下呼吸和輕微晃動；身體裡的光點緩慢流動（概念圖） |
| 移動 | 一跳一跳地前進（跟 Poring 一樣）：跳的頻率跟移動速度連動，落地時壓扁、起跳時拉長 |
| 攻擊 | 向目標壓縮再彈出，在命中時間撞到目標 |
| 受擊 | 整體晃動（彈簧），晃動幅度依受擊硬直時間 |
| 死亡 | 塌陷、變透明、消失 |

- 沒有骨架。變形用「位置＋速度＋彈簧」的簡單模擬，結果傳給著色器。
- 半透明和內部光芯在材質做（04 第 17 節）。

### 7.2 毛絨蟲（fluffy_caterpillar）

| 狀態 | 做法 |
|---|---|
| 站立 | 體節輕微起伏；觸角用彈簧骨頭（SpringBoneSimulator3D）晃動 |
| 移動 | 頭部沿著路徑走，後面的體節跟著頭走過的軌跡（ChainIK3D 或 SplineIK3D），再加上一波一波的起伏；短腳交替擺動 |
| 攻擊 | 抬起前半身再往前撞 |
| 受擊 | 縮一下、觸角大幅晃動 |
| 死亡 | 捲成一團、倒向一邊、消失 |

- 骨架由 04 的管線自動建立：沿著身體的 6 節體節骨頭、兩根觸角、每節左右各一隻腳（04 第 10 節）。

### 7.3 小樹精（young_treant）

| 狀態 | 做法 |
|---|---|
| 站立 | 人形的待機動作，加上頭頂枝葉的彈簧晃動 |
| 移動 | 沉重的走路動作（人形動作庫的怪物走路） |
| 攻擊 | 手臂橫掃 |
| 受擊 | 後仰，枝葉大幅晃動 |
| 死亡 | 往後倒下，葉子變黃、枯萎（材質參數） |

- 外型是人形，用人形骨架和動作（04 第 9、10 節）；枝葉用 SpringBoneSimulator3D。
- 動作的來源跟玩家一樣（Mixamo、Quaternius），選比較沉重、像生物的動作。

### 7.4 共通

- 移動動作的速度跟實際移動速度連動，避免滑步（跟 05-D17 一樣）。
- 攻擊在命中時間（`attack_hit_ms`）打到目標：果凍怪和毛絨蟲由程序化動畫自己對齊，小樹精用動作標記（05-D10）。
- 怪物也會面向移動方向和攻擊目標，轉身用平滑旋轉。
- 死亡動作播完後淡出，大約 2 秒。

## 8. 動作檢視器（07-D12）

- 用 05 第 11 節的檢視器，選怪物 ID。
- 可以看站立、移動、攻擊、受擊、死亡五種狀態；移動可以設定速度（預設用資料的移動速度）。
- 程序化動畫的參數（彈簧、跳的高度和頻率、體節波動）可以在檢視器即時調整，滿意後存回外觀設定。
- 自動截圖：每隻怪物每種狀態截開始、中間（攻擊的命中點）、結尾。

## 10. 測試與驗收方式

**M4：**
1. 檢視器裡三隻怪物的五種狀態都能播放，沒有錯誤；自動截圖給我先看，再請你確認。
2. 果凍怪跳著移動、落地壓扁；毛絨蟲的體節跟著頭的軌跡；小樹精的枝葉會晃。
3. 攻擊動作的命中點跟 `attack_hit_ms` 相差不超過 1/60 秒。

**M6（整合測試，固定亂數種子）：**
4. 被動怪物：玩家走近不會攻擊；被打會反擊，並追到追擊距離以外就放棄。
5. 主動怪物（測試用的資料）：玩家進入視野就追過來；抵達後 3 秒保護中、隱匿中的玩家不會被當目標。
6. 閒晃：每 4～5 秒移動一次，位置都在導航網格上。
7. 撿東西：果凍怪會撿地上的物品；在撿取優先權時間內不會撿。
8. 生成和重生：地圖載入時數量正確；死亡後在設定的時間重生，位置在生成區內。
9. 效能：單張地圖 200 隻怪物、20 名玩家時，伺服器每個 tick ≤ 10 ms（01 第 14 節）。

## 11. 風險與備案

| 風險 | 影響 | 備案 |
|---|---|---|
| 程序化動畫做不出概念圖的可愛感 | 表現不好 | 參數都能在檢視器調；必要時改用綁骨加手做的動作 |
| Godot 4.6 新的 IK 節點有錯誤 | 毛絨蟲的體節不正常 | 改用腳本自己算體節位置（不用 IK 節點） |
| 200 隻怪物的 AI 和尋路太重 | tick 超時 | 思考已錯開；沒有目標的怪物不重算路徑；必要時降低閒晃頻率 |
| 很多怪物同時追同一個人 | 擠成一團（怪物互相穿透） | 照 RO，本來就會重疊；畫面上可以接受 |

## 12. 與 RO 原制不同之處（待檢視）

| 項目 | RO 原制 | 本專案 | 理由 |
|---|---|---|---|
| 怪物的造型和名稱 | Poring、Fabre、Willow | 照概念圖的原創造型和名稱 | 00-A02、00-S12；數值和行為照 RO |
| 怪物的動作 | 2D sprite 的固定影格 | 3D 程序化動畫和人形動作 | 00-A11 |
| 南方草原的生成數量 | prt_fild08 的數量 | 參考它，依地圖大小調整 | 地圖大小不同 |

除了上表，本文件其他部分都照 RO：
- 怪物的數值、屬性、種族、體型、行為（AI 類型和旗標）
- 思考間隔 100 毫秒、閒晃間隔 4～5 秒
- 被動和主動、反擊、換目標、協助、撿東西的規則
- 追丟目標後不回到生成點
- 生成和重生的寫法（基本時間＋隨機時間）、重生至少 1 秒
- 不攻擊抵達保護中的玩家、看不到隱匿的玩家

## 15. 跟計畫大綱不同的地方

| 大綱 | 本文件 | 理由 |
