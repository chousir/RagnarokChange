## 3. 流程

```text
main ──┬────────────────────────────────────────────────────────── 合併（你確認後）──► main
       │                                                            ▲
       └─ m1-map-walk：M1-a ─► M1-b ─► M1-c ─► M1-d ─► M1-e ─────────┘
                       標籤     標籤     標籤     標籤     標籤
                       m1-a    m1-b    m1-c    m1-d    m1-e

一批的流程：
  1. 寫程式和測試
  2. check.ps1 全部通過
  3. 自動截圖，我先看過（01-D11）
  4. 提交（英文訊息，例如 feat(m1-a): add map white-box），打標籤
  5. 需要你看的截圖整理在 artifacts/review/<批次>/，等你方便時確認
失敗：備份分支 → 退回上一個標籤 → 重做
```

- 提交訊息的格式照 01 第 13.1 節：`類型(批次): 摘要`，例如 `feat(m1-a): add map white-box`、`test(m0-b): cover duplicate keys`。
- 每批結束時，把這一批的結果（通過的測試、量到的效能、遇到的問題）寫進 `artifacts/review/<批次>/report.md`，給你看的時候一起看。

### 4.6 第一版的驗收條件（11-D01）

1. Kronenberg 王都和南方草原都可以走遍，傳送點雙向都能用，換圖時淡出淡入。
2. 動作檢視器裡，四個職業（女性）× 6 種武器的所有動作、10 種表情、三隻怪物的五種狀態都看得到，沒有缺動作。

4. `check.ps1` 在乾淨的 clone 上通過；冒煙測試沒有錯誤。
5. 你看過截圖並確認。
